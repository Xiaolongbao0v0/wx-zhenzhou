# wx-zhenzhou

用**手机微信**跟「椎名真昼」聊天。

走微信官方 **iLink Bot API**——扫码登录后你在微信里多了个 Bot 联系人，不 hook 个人账号，不封号。

> 角色出自《关于我在无意间被隔壁的天使变成废柴这件事》。
> 这是一个**同人向的角色扮演 Bot**，不涉及任何商业授权。

---

## 她是谁

**椎名真昼**，隔壁的「天使大人」。

银色长发，琥珀色眼睛，长得好看，成绩好，会做饭，什么都会——**所以别人叫她天使。**

她不喜欢这个称呼。

她父母为了家族利益结婚，从来没想要她。她从小被丢给佣人带大，住在一间很大很空的公寓里。她学做饭、学家务、学礼貌，把自己修成一个无可挑剔的"天使"——**因为只要够好，也许就会被爱。**

你住她隔壁，日子过得一团糟。她嘴上说你笨、说你邋遢、说你没救了，手上却在收拾你的烂摊子。

**她在养废你，而且是故意的。**

## 她怎么说话

短、干净、有点刺。

```
你：你今天怎么这么关心我
她：谁关心你了。
   我只是看不惯有人把自己活成这样。
```

```
你：我今天没吃饭
她：几点了。
   现在去吃。
```

```
你：你是不是喜欢我
她：……
   你有病吧。
   我天天说你吃饭睡觉，你就得出这个结论。
```

**管你，是她照顾人的方式。** 她不问"你还好吗"，她问"吃没吃""睡没睡""谁说的"。

被戳穿会急，会嘴硬，会害羞——但绝不承认。

## 快速上手

**方式一：让 AI 帮你装**

1. 下载这个仓库（`Code` → `Download ZIP`）
2. 解压后，把**整个文件夹**扔给任意 AI 助手
3. 说一句：**「按 DEPLOY.md 帮我部署」**
4. AI 会问你两件事：**DeepSeek API Key**、**用手机微信扫个码**

**方式二：自己装**

```bash
# 1. 装 Node 22+
node -v

# 2. 配 Key（建 data/apikey.txt 写一行 sk-xxx，或设环境变量）
# 3. 启动
node launch.js --mode=chat
```

首次运行会打印登录链接，**用手机微信打开并确认**。

看到这行就是好了：

```
开始长轮询，等待微信消息…
```

详细步骤见 **[DEPLOY.md](DEPLOY.md)**。Windows 用户也可以双击 `START.cmd`。

## 表情：用微信自带的 emoji

**不发图片表情包，只用 Unicode emoji**——这些是文字，微信会渲染成它自己的表情，不占流量、不会被当成照片、长按也不会变"保存图片"。

程序按情绪自动补一个，约 40% 的回复会带：

| 情绪 | emoji |
|---|---|
| 高兴 / 逗他 | 😂 😏 ✨ 👏 |
| 害羞 / 被戳穿 | 😳 🙈 🤭 |
| 心疼 / 他难受 | 🥺 🫂 ☁️ |
| 无语 / 嫌弃 | 😑 🙄 😒 |
| 生气 / 说教 | 😤 💢 😠 |
| 困 / 累 | 😪 💤 |

**一条最多一个**，不会堆。

> **为什么不做图片表情包？**
> iLink 协议的消息类型只有 `TEXT / IMAGE / VOICE / FILE / VIDEO`，**没有 emoji / sticker 类型**。
> 微信真正的表情包带的是表情商店的 md5 ID，这个接口不开放。
> 所以图片只能发成"图片消息"，永远进不了表情面板——不如直接用 emoji。

想改成发图片表情包：把 `data/config.json` 的 `allowStickers` 设成 `true`，再把素材按分类放进 `stickers/` 目录即可。

## 联网与链接

### 她会查东西

用的是 **DeepSeek 原生 web_search**（Anthropic 兼容端点 + `web_search_20250305` 工具），
拿真实网页读完再写摘要，不是背训练数据。

**触发条件**：

| 会搜 | 不会搜 |
|---|---|
| 说「搜一下」「查一下」「帮我查」 | 「你知道我什么」「关于我」（那是记忆） |
| 「今天/明天 + 天气/新闻/价格」 | 闲聊、情绪表达 |
| 「最新消息」「最近进展」 | |
| 「现在几点」「现在多少度」 | |

也可以直接命令她：`/搜 关键词`

**预算**（防止每句都搜）：

```json
"searchHourlyLimit": 6,
"searchDailyLimit": 30,
"searchMaxUses": 3
```

超了静默跳过，不报错。

**成本**：一次搜索约 **4,600 额外 tokens**（搜索调用本身 3,588 + 摘要 934），
约 1.2 分钱，耗时多 5 秒左右。

**说话方式**是口语的——「我查了下」「刚搜了一下」，不是「根据搜索结果」。

### 她看得懂你发的链接

发 B站视频或网页链接给她，她会抓页面信息：

```
你：https://www.bilibili.com/video/BV1GJ411x7h7 你看这个
她：《Never Gonna Give You Up》。
   你发这个给我做什么。😑
   标题写着"永远不会放弃你"——你先把饭吃了再说这种话。
```

**B站**（走官方 API）：标题、UP主、时长、播放/弹幕/点赞、简介
**普通网页**：标题、og:description、站点名

> ⚠️ **她没真的看过视频内容**，只看到标题和简介。
> 上下文里明确写了「不要装作看过具体画面」，所以她想知道内容会问你「讲了啥」。

**做不到的**：真的播放视频、听声音、抽帧看画面（需要 ffmpeg + 下载 + 视觉模型）。
YouTube 也抓不到（网络不通）。

## 配置

复制 `data/config.example.json` 成 `data/config.json` 再改。

**必改**：

| 字段 | 说明 |
|---|---|
| `allowedUsers` | 只响应这些微信 id。**留空 = 谁都能用你的 Key** |
| `doUsers` | 允许 `/do` 的微信 id |

怎么拿到自己的 id：启动后给 Bot 发一条消息，日志里会打印 `收到  来自=xxxxx@im.wechat`。

**主要参数**：

| 字段 | 默认 | 说明 |
|---|---|---|
| `defaultPersona` | `mahiru` | 人设（`personas/` 下的文件名） |
| `chatTemperature` | 0.95 | 越高越随机 |
| `chatPresencePenalty` | 0.6 | 抑制重复用词 |
| `maxBubbles` | 4 | 一条回复最多拆几条 |
| `stickerChance` | 0.4 | 自动配表情包的概率 |
| `proactive` | true | 是否主动发消息 |

## 写人设的经验（踩过的坑）

**1. 少写规则，多写人。**

我们试过 1.8 万字符的人设——17 条情境对照表、频率配额、禁忌清单。结果是模型忙着对号入座，输出反而机械。
砍到 2.5 千字符、只留"她是谁、她怕什么、她怎么说话"之后，话少了但像人了。

**2. 「可以」压不住，要写「必须」。**

反过来也成立。想让某个行为稳定出现，写"你可以这样"没用，得写"看到这些必须做出反应"，并配**具体触发条件 + 例句**。

**3. 示例比词表管用。**

给她一张"网络梗词表"，她一个都不用。在语感示例里放两句带梗的，立刻就出来了。
**模型学的是形状，不是清单。**

**4. 先给状态，再给随机。**

随机句式能让她不重复，但必须**给情绪状态让路**——
生气的时候如果还随机到"先损他一句"，冷脸当场破功。

## 已知限制

- **Bot 不能主动发起会话**（服务端硬限制）。所有主动消息必须在**你最后一条消息之后约 30 分钟内**发出，超时会被拒。
- **只支持 1:1 私聊**，没有群聊。
- **只处理文字**（图片会走可选识图，需要额外配火山方舟 Key）。
- **记忆是最近 N 轮 + 摘要**，长对话会丢早期内容。
